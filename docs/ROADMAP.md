# 开发路线图

## 阶段 0：项目初始化（第 1 周）
- [ ] 初始化 Tauri v2 + 前端模板项目。
- [ ] 配置 Rust CI（clippy、fmt、test）。
- [ ] 确定代码规范与分支策略（Git Flow / Trunk）。
- [ ] 搭建本地开发环境文档。

## 阶段 1：核心本地服务（第 2-3 周）
- [ ] 实现 Axum HTTP 服务，暴露 `/v1/models`、`/v1/chat/completions`。
- [ ] 实现配置加载与热重载（YAML 格式）。
- [ ] 实现基础路由引擎：模型别名 -> 后端提供商。
- [ ] 实现请求转发与流式/非流式响应透传。
- [ ] 集成测试：用 mock 上游验证转发逻辑。

## 阶段 2：配置与密钥管理（第 3-4 周）
- [ ] 设计并实现配置 schema（提供商、模型映射、Fallback、限流）。
- [ ] 集成 keyring，实现 API Key 安全存储。
- [ ] 前端 UI：提供商增删改查、模型映射编辑。
- [ ] 配置文件导入/导出与备份。

## 阶段 3：可靠性增强（第 4-5 周）
- [ ] 失败重试与 Fallback 策略。
- [ ] 后端健康检查与自动隔离。
- [ ] QPS / 并发限流。
- [ ] 本地服务异常自动重启。
- [ ] 日志与 SQLite 用量统计。

## 阶段 4：监控与体验优化（第 5-6 周）
- [ ] 前端监控面板：服务状态、模型列表、实时请求数。
- [ ] 用量统计页面：按天/周/月展示请求量与 Token 消耗。
- [ ] 日志查看器与错误提示。
- [ ] 一键复制本地 Base URL 与 API Key。

## 阶段 5：跨平台打包与发布（第 6-7 周）
- [ ] Windows `.msi` 打包与签名。
- [ ] macOS `.dmg` / `.app` 打包、签名与 Notarize。
- [ ] GitHub Actions Release 工作流。
- [ ] 自动更新机制（Tauri Updater）。
- [ ] 编写用户手册与快速开始文档。

## 阶段 6：扩展与迭代（第 8 周起）
- [ ] 支持更多端点：`/v1/embeddings`、`/v1/completions`。
- [ ] 非 OpenAI 兼容后端的请求/响应转换模板。
- [ ] 插件机制预留接口。
- [ ] 根据用户反馈优化 UI 与稳定性。

## 里程碑
| 里程碑 | 时间 | 交付物 |
|--------|------|--------|
| M1 | 第 3 周末 | 可运行的本地 API 转发服务（命令行可用） |
| M2 | 第 5 周末 | 带 UI 的 Alpha 版本，支持双平台手动安装 |
| M3 | 第 7 周末 | 正式版 v1.0.0，支持自动更新与签名分发 |
